# Explicit bounded Romance source components

This ordinary Python package adopts the reviewed source under
`qualification/romance_semantic_lowering/romance-prototype/` for explicit,
inactive application composition. It does not load source by filename, add a
search path, install dependencies, register languages or select a profile.

`coverage.py` changes only three imports to this package's relative namespace.
The retained frontend modules, inert vendor initializer, MIT license,
modification record and fail-closed patch are copied byte for byte. Each adopted
file's source and resulting SHA-256 are in `provenance.json`; upstream files
also retain their original commit, Git blob and SHA-256. The original
qualification packet is unchanged. No pronunciation rule is introduced here.

`compose_customer_tokenizer(..., romance_locales=("es", "fr", "pt-br"))` adds
only the explicitly requested routes to the existing English owner. The
application composition never accepts bare `pt` or `pt-pt` and never picks a
Portuguese dialect. European Portuguese remains in the unchanged research
algorithm but is not an admitted application route. Phone service `pt` remains
unavailable to this composition; its locale cannot imply Brazilian Portuguese.

These are bounded phrase/representation routes, not complete language support.
They preserve source spans, whole-phrase French context and semantic phone and
stress distinctions. Numbers, currency, unsupported scripts, unknown graphemes
and unrepresentable phones reject the complete input. Existing French liaison
and Portuguese glide quality witnesses remain unresolved. Accepted outputs are
not native-pronunciation goldens or acoustic approval.

Explicit injection uses the existing customer profile gate, Kokoro tokenizer,
model batching and caller-selected voice. Importing or constructing these
components changes no application default or environment setting. The existing
eight-language-family and 54-voice requirements remain unchanged; frozen
packaging, full coverage, listening, signed inclusion and installed-app
qualification are separate outstanding work.
