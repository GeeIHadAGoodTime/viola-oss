# Viola macOS Desktop Requirements
#
# Runtime dependencies for the macOS desktop build (installer/macos/build_macos_app.sh
# -> PyInstaller .app bundle). Goal: parity with requirements_desktop.txt (Windows) /
# requirements_linux.txt so a Mac user gets the SAME capability surface (login,
# voice/wake, agent, music, playback, phone, settings). The ONLY things dropped
# from the desktop set are packages that are genuinely Windows-only (WASAPI/COM/
# Win32) or Linux-only (Secret Service D-Bus); every cross-platform dependency is
# kept, plus the macOS-only pyobjc framework bindings the darwin code paths
# already import at runtime (services/computer_use/input.py,
# services/computer_use/window_manager.py, intent/tools/vision_tools.py,
# audio_core/capture/coreaudio_capture.py, services/notifications/macos_notification.py).
#
# This manifest did not exist before #2594: `build_macos_app.sh` ran PyInstaller
# directly with no pip-install step, so a bundle only worked when the box
# happened to have these hand-installed (which is exactly why the gap stayed
# invisible on the Mac dev box). See #2594 acceptance oracle.
#
# Pinned for reproducible builds. Keep in lockstep with requirements_desktop.txt /
# requirements_linux.txt when a cross-platform dependency is added or bumped there.

# Wake word detection
# #4786: openwakeword IS required. Ground-truthed against the actual shipped
# violawake_data/trained_models/temporal_cnn.onnx via onnxruntime: its ONNX
# graph declares input "embeddings" shape (batch, 9, 96) -- the OpenWakeWord
# embedding shape, not a raw mel-spectrogram -- so violawake/engine.py's
# ViolaWake._load_model() always routes it through _load_onnx_mlp(), which

# raises ImportError the moment the wake engine loads (this entry was

# retrained/replaced temporal_cnn.onnx with this embedding-based
# architecture -- see requirements_linux.txt's identical fix for detail).
